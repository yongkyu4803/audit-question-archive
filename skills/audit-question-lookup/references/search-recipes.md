# 검색 예 (Drive 연결 `search_files`)

`<카드폴더>` 는 `_INDEX.md` 가 들어 있는 `카드` 폴더 id, `<파싱폴더>` 는 `파싱` 폴더 id 다. 결과의 `nextPageToken` 이 있으면 `pageToken` 으로 이어서 조회한다. 본문을 읽을 필요가 없으면 `excludeContentSnippets: true` 로 메타데이터만 받는다.

| 하고 싶은 일 | 질의 |
|---|---|
| 마스터 목록 찾기 | `title = '_INDEX.md' and mimeType = 'text/markdown'` |
| 카드 폴더 전체 | `parentId = '<카드폴더>'` |
| 카드 본문에 단어가 있는 것 | `'<카드폴더>' in ancestors and fullText contains '집행률'` |
| 질의서 본문에 단어가 있는 것 | `'<파싱폴더>' in ancestors and fullText contains '집행률'` |
| 특정 건의 파싱본 | `title = '{id}.파싱.md'` (결과의 부모가 `파싱` 폴더인지 확인) |
| 특정 건의 카드 | `title = '{id}.카드.md'` |
| 최근 갱신순 | 위 질의에 `orderBy: 'modifiedTime desc'` |

## 읽기 결과 해석
- `read_file_content` 가 돌려주는 글은 마크다운 기호가 이스케이프되어 있다 (`\_`, `\#`, `\[`, `\---`). 표의 `|` 구조는 유지된다.
- 카드·파싱본 맨 위의 `---` 로 둘러싼 부분이 머리말이다. 카드는 id, 기관, 제출일, 회신 상태, 원본 참조(`source_name`)가 있고, 파싱본은 원본 참조와 변환 정보(쪽 기준 등)가 있다.
- 파싱본 본문의 `<!-- 구역 N — 쪽 번호 근사 -->` 표지는 쪽(또는 구역) 경계다.

## 알려진 동작
- 올린 직후 몇 분은 검색과 읽기가 비어 있을 수 있다.
- 결과가 적어도 다음 쪽이 붙을 수 있고, 첫 쪽에 관련 없는 파일이 먼저 나올 수 있다.
- 카드·파싱본이 교체되면 같은 이름의 새 파일이 생기고 옛 파일은 휴지통으로 간다. 휴지통 파일(`trashed = true`)은 무시한다. 같은 이름이 둘 보이면 수정 시각이 늦은 것을 쓰고 관리자에게 알린다.
- `.hwp`/`.hwpx` 는 내용을 읽지 못한다 (원본은 어차피 공유되지 않는다).
