# Drive 구조와 세 파일의 짝

## Drive 폴더 (소유: 의원실 전용 계정)

```
국감 질의서 아카이브/
├── 원본/   한글 원본만. 관리자만 접근.  _처리기록.json (관리자 전용)
├── 파싱/   {id}.파싱.md        팀원 뷰어
└── 카드/   {id}.카드.md  +  _INDEX.md   팀원 뷰어
```

- 팀원에게는 `파싱/` 과 `카드/` 만 공유한다. `원본/` 은 공유하지 않는다.
- 한글 원본은 올린 이름 그대로 둔다 (이름 변경 금지). 사용자에게는 카드의 `source_name` 으로 파일명만 안내한다.

## 같은 id 로 묶이는 세 파일

```
{제출일}_{상임위}_{피감기관}_{질의자}_{유형}_v{버전}
2026-10-14_기획재정위원회_가나다진흥원_홍길동_서면질의_v1
```
| 파일 | 이름 |
|---|---|
| 한글 원본 | (Drive `원본/` 의 원래 이름) |
| 파싱본 | `{id}.파싱.md` |
| 카드 | `{id}.카드.md` |

이름 조각(상임위·기관·질의자)에는 공백과 밑줄을 쓸 수 없다. 같은 질의자가 같은 날 같은 기관에 같은 유형을 둘 이상 내면 id 가 겹치므로 버전(`_v2`)으로 구분한다.

## 원본 참조 표시

파싱본과 카드 맨 위(머리말)에 같은 네 줄이 들어간다.
```
source_name: 2026-10-14_기획재정위원회_가나다진흥원_홍길동_서면질의.hwpx
source_drive_id: 1AbC...
source_drive_url: https://drive.google.com/file/d/1AbC.../view
source_sha256: 49091664...
```
`check.py` 는 파싱본과 카드의 참조가 서로 같은지, 내려받은 원본의 해시가 그대로인지 본다.

## 원본 파일명 규칙 (권장)

`제출일_상임위_기관_질의자_유형[_v버전].hwpx` — 예: `2026-10-14_기획재정위원회_가나다진흥원_홍길동_서면질의.hwpx` (제출일은 `YYYY-MM-DD` 또는 `YYYYMMDD`).
한글 파일 안에는 상임위·질의자·제출일이 없다. 이름이 규칙을 따르면 동기화 때 메타를 자동으로 읽고(관리자는 확인만), 따르지 않으면 관리자에게 하나씩 물어야 한다.

## 마스터 목록 `카드/_INDEX.md`

열: id, 제출일, 상임위, 피감기관, 질의자, 유형, 버전, 회신, 주제, 원본 파일명, 카드, 파싱.
게시 대상 카드(공개·내부 + 개인정보 확인 완료)에서 `rebuild_index.py` 가 만든다. 원본이나 카드·파싱본이 추가될 때마다 동기화 6단계가 새 목록을 올린다.

## 관리자 PC 작업본

```
<작업본>/
├── 원본캐시/   {drive_id}__{원본 파일명}   내려받은 한글 원본 (올리지 않음)
├── 파싱/       {id}.파싱.md
├── 카드/       {id}.카드.md, _INDEX.md
└── _state/     처리기록.json (처리한 원본, 올린 파일의 Drive id·해시, Drive 폴더 id), listing.json, plan.json
```
Drive 의 `파싱/`·`카드/` 는 작업본에서 올라간 사본이다. 고치는 곳은 작업본이고, Drive 에서 직접 고치지 않는다 (다음 교체 업로드 때 덮인다).

## 처리기록 (`_state/처리기록.json`, Drive 사본은 `원본/_처리기록.json`)
- `folders`: 원본/파싱/카드 Drive 폴더 id
- `originals`: Drive 원본 파일 id → 이름, etag, 수정시각, 해시, 만들어진 카드 id (중복 처리 방지, 바뀐 원본 감지)
- `uploads`: 올린 파일 → Drive 파일 id, 올릴 때의 해시 (교체·내림 판단)
