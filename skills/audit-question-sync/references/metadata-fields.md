# 카드 필드

카드는 요약이 아니라 **원본으로 돌아가는 색인**이다. 원본을 다시 열지 않고도 무엇인지 알아보게 하고, 필요할 때 어디를 볼지 알려 준다.

## 머리말 필드

| 필드 | 필수 | 값 |
|---|---|---|
| `id` | O | `{제출일}_{상임위}_{기관}_{질의자}_{유형}_v{버전}`. 필드로 만든 값과 같아야 한다 |
| `year`, `committee`, `agency`, `author`, `submitted`, `kind`, `version` | O | id 를 이루는 값. `kind`: 본질의·서면질의·요구자료·보충질의·종합질의 |
| `status` | O | 제출, 수정제출, 폐기 |
| `topic` | | 목록 '주제' 열의 한 줄 (30자 안팎, `\|` 금지) |
| `source_name` | O | Drive `원본/` 에서의 한글 원본 파일명 |
| `source_drive_id` | O | 그 파일의 Drive 파일 id |
| `source_drive_url` | | 관리자용 링크 |
| `source_sha256` | O | 내려받은 원본의 해시. 원본이 바뀌면 점검에서 오류 |
| `parse_file` | | `{id}.파싱.md` |
| `parse_page_mode` | | `page`(한컴 저장본의 실제 쪽) 또는 `section`(구역 근사) |
| `visibility` | O | 공개, 내부, 비공개 |
| `privacy_checked` | | 사람이 개인정보·비공개 자료를 확인했으면 `true`. `true` 이고 비공개가 아니어야 Drive 에 올라간다 |
| `reply_status` | O | 미수령, 수령, 부분수령, 해당없음 |
| `reply_date` | 회신 시 | 회신을 받은 날 |
| `tags`, `prior`, `related_laws` | | 주제어, 이어지는 이전 카드 id, 다룬 법령명 |

## 본문
1. **질의 요지**: 질의 번호, 한 줄 요지, 원문 위치. 원문 위치가 없으면 원문을 다시 찾을 수 없는 카드가 된다.
2. **핵심 수치 (원문 표기 그대로)**: 반올림·단위 변환·의역 없이. 출처가 원문에 없으면 "원문에 출처 없음".
3. **후속**: 날짜 + 한 줄. 제출 당시 내용은 고치지 않고 아래로 덧붙인다.
4. **한계·주의**: 제출 후 알게 된 오류, 비공개 자료 포함 여부, 인용 시 주의점.

## 채우는 방법
- 파싱본(`파싱/{id}.파싱.md`)을 읽어 옮긴다. 기억이나 다른 파서에 의존하지 않는다.
- 파싱본에는 쪽(또는 구역) 경계마다 `<!-- 쪽 N -->` / `<!-- 구역 N — 쪽 번호 근사 -->` 표지가 있어 위치를 적는 데 쓴다.
- 값이 원문에서 확인되지 않으면 비워 두고 이유를 `한계·주의` 에 적는다.
- 고친 뒤에는 `rebuild_index.py`(release.py 가 자동으로 실행) 와 `check.py`, 그리고 `plan_upload.py` 로 Drive 에 교체 업로드한다.
