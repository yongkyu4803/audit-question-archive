# 후속 추적: 회신, 시정요구, 다음 해 연결

질의서는 제출로 끝나지 않는다. 가치는 **다음 해 국감에서 "작년에 뭘 물었고 어떻게 답했나"를 바로 꺼낼 수 있는지**에서 나온다.

## 회신을 받았을 때 (관리자, 작업본에서)
1. 카드 머리말의 `reply_status` 를 `수령`(또는 `부분수령`)으로, `reply_date` 를 채운다. (`release.py <id> --reply-status 수령 --reply-date YYYY-MM-DD`)
2. 카드 `후속` 에 한 줄 덧붙인다. 예: `2026-11-02 회신 수령. 질의 2번 답변 누락.`
3. 회신 문서 자체를 보관하려면 Drive `원본/` 에 올려 두고(관리자 전용), 카드 후속에 그 파일명을 적는다. 회신 내용은 필요한 만큼만 카드에 옮기고, 비공개 자료가 섞였는지 확인한다.
4. `plan_upload.py` → 카드와 목록이 교체 업로드된다 (새 파일을 올려 기록한 뒤 옛 파일을 휴지통으로).
5. `check.py` 로 오류가 없는지 본다.

답변이 일부만 왔으면 `부분수령` 으로 하고 어느 질의 번호가 비었는지 `후속` 에 적는다. 회신이 필요 없는 성격이면 처음부터 `해당없음`.

## 시정·조치 요구를 추적할 때
`후속` 에 한 줄씩 쓴다.
```
- [요구] 질의 3: 산출근거 공개 요구 (2026-10-14)
- [이행] 2027-03-10 기관이 홈페이지에 공개한 것 확인 (확인 방법: 해당 페이지 직접 열람)
- [미이행] 2027-09-01 기준 공개되지 않음
```
이행은 **직접 확인한 근거**(공개된 자료, 회신 문서)가 있을 때만 적고 확인 방법을 남긴다. 확인하지 못했으면 `확인불가`. 이행되었으리라 추정하지 않는다.

## 다음 해 질의와 연결
1. `카드/_INDEX.md` 나 `tags` 로 같은 `피감기관` 의 이전 카드를 찾는다.
2. 새 카드의 `prior` 에 이전 카드 id 를 적는다. 이전 카드에도 `후속` 으로 "2027 국감에서 재질의 → {새 id}" 를 덧붙인다.
3. 과거 회의록의 실제 답변은 `assembly-minutes-search` 로 확인하고, 카드에는 회의 일자와 위치만 적는다.

## 정기 점검 (연 1회, 국감 2~3개월 전)
- `reply_status` 가 `미수령` 인 채 오래된 카드를 모아 재요구 대상인지 판단한다.
- `[요구]` 만 있고 `[이행]`/`[미이행]` 이 없는 항목의 현황을 확인한다.
- `check.py` 와 `ledger.py status` 로 확인 대기·업로드 대기 건을 정리한다.
