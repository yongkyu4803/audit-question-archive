# 공개 구분과 개인정보: 올리기 전 관문

이 문서는 점검 목록이다. 법적 판단을 대신하지 않으며, 애매하면 올리지 말고 담당자나 법무 담당에게 확인한다. 법령이나 규정을 근거로 쓸 때는 기억으로 인용하지 말고 법령 검색 도구로 조문을 확인한다.

## 왜 관문이 필요한가
팀원이 보는 `파싱/` 과 `카드/` 에는 **질의서 본문 전체**가 들어간다. 올라간 뒤에는 뷰어가 읽을 수 있으므로, 올리기 전에 사람이 확인한다.

## 공개 구분 (`visibility`)
| 값 | 쓰는 경우 | Drive 에 올림 |
|---|---|---|
| 공개 | 이미 공개된 자료만 인용했고 질의서도 공개해도 되는 것으로 확인된 경우 | 확인 후 올림 |
| 내부 | 기본값. 의원실 안에서만 쓰는 경우 | 확인 후 올림 |
| 비공개 | 비공개 지정 자료, 개인정보, 내부 제보, 보안이 필요한 내용 | 올리지 않음 |

## 점검 목록 (`privacy_checked: true` 로 바꾸기 전)
- [ ] 개인을 식별할 수 있는 정보(이름, 연락처, 주소, 주민등록번호, 계좌 등)가 본문에 들어 있지 않은가? 있다면 필요한 범위인가?
- [ ] 기관에서 받은 자료 중 비공개나 대외비로 지정된 것이 본문에 포함되지 않았는가?
- [ ] 내부 제보에 의존한 내용이라면 제보자가 특정되지 않도록 처리했는가?
- [ ] 카드의 `핵심 수치` 에 비공개 자료의 수치를 옮겨 적지 않았는가?

확인이 끝나면 `release.py <id> --privacy-checked true`. 이 확인은 사람이 하고, 스크립트나 Claude 가 임의로 바꾸지 않는다.

## 이미 올라간 건을 내릴 때
비공개로 바꾸거나 확인을 취소하면(`release.py … --visibility 비공개` 또는 `--privacy-checked false`) `plan_upload.py` 가 remove 작업(Drive 휴지통으로)을 만든다. 휴지통에서 복원할 수 있다. `check.py` 는 올라가 있으면 안 되는 카드를 오류로 알린다.

## 공유 범위
- Drive 권한은 폴더 단위다. 팀원에게는 `파싱/`·`카드/` 만 뷰어로 공유하고 `원본/` 은 공유하지 않는다.
- 개별 이메일로만 공유한다. "링크가 있는 모든 사용자"는 쓰지 않는다. 자세한 규칙은 `team-workflow.md`.
- 외부(언론, 다른 의원실)에 전달하기 전에는 `visibility` 와 `privacy_checked` 를 다시 확인한다.
